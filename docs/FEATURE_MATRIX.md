# CallFlow 功能验收矩阵

> 本文档把此前审计中提炼出的 88 项通用功能需求，转换为独立实现的验收清单。
> 判断标准不是“页面存在”或“接口存在”，而是：页面可操作、服务端有真实逻辑、数据可持久化，并有对应测试或人工验证记录。

## 状态定义

| 状态 | 含义 |
| --- | --- |
| 已实现并验证 | 前端、服务端与数据库逻辑完整，已通过自动化测试或浏览器端到端验证 |
| 已实现但尚未验证 | 功能已编码，但缺少专门的自动化断言，或只有部分路径被覆盖 |
| 模拟模式可用 | 通过明确的模拟适配器工作，界面标注“模拟”，不声称接入了真实外部服务 |
| 需要外部设备或配置 | 代码接口与配置位已准备，但需要真实电话、STT、LLM 或飞书凭据才能验证 |
| 未实现 | 当前版本没有对应能力 |

## 验证基线

- `npm run build`：TypeScript 严格模式通过，Vite 构建成功（2451 modules；CSS 83.22 kB / gzip 15.43 kB；JS 535.63 kB / gzip 149.60 kB；仅有 chunk 体积提示）。
- `NODE_ENV=test npm test`：**26 pass / 0 fail**。
- `npm run test:smoke`：**30 PASS / 0 FAIL**（Playwright + Edge，覆盖登录、预约冲突、模拟通话全链路、全部路由、权限、响应式与演示数据重置）。
- `npm run screenshots`：12 张界面截图，人工检查。
- 模拟类结果在 API 响应中带 `simulated: true`，在界面中显示“模拟”标识。
